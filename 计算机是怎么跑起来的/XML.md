
XML(Extensible Markup Language 可扩展标记语言),那什么是标记语言?我们常见的HTML(Hypertext Markup Language 超文本标记语言),一般后缀为 .html 那么 XML 就是 .xml 咯

标记语言:通过添加标签为数据赋予意义的行为称为“标记”​。为标记行为定义规则的语言就是“标记语言",像 html head title body 这些用 "<" 和 ">"都是标签,他们都有表示含义 title表示网页的标题 


来看看XML为何诞生

在早期,每个软件公司都用自己的私有格式存储数据,系统之间交换数据,无法读懂对方的私有格式,导致无法交换

后来,SGML出现,它的核心思路为 把数据的结构和内容分开，用"标签"来描述内容是什么。
```
<姓名>张三</姓名>
<年龄>25</年龄>
```
这样做思路是对的,但 SGML 很复杂,因为他什么都需要去兼容,像
```
<emphasis>重要内容</emphasis>
<emphasis/重要内容/
重要内容</emphasis>
```
对于 SGML 来说都是合法写法,但前提是:需要你写好所有的规则

接下来是 HTML ,像

```html
	<h1>标题</h1>
	<p>段落</p>
	<b>加粗</b>
```
他解决了页面展示的问题,但是,它无法知道 "数据"是什么
```html
<b>25</b> //这是年龄?价格?编号?
```

那么 XML 诞生了

W3C（万维网联盟）意识到：互联网需要一种既简单又能描述数据含义的语言于是它精简了 SGMl,获得了以下优点
- 人能方便读懂
- 设计简洁
- 能够在互联网上使用

那 XML 精炼了哪些内容

首先 XML 的最小单位:元素,由三部分组成

```html
<姓名>        张三       </姓名>
开始标签      内容       结束标签
```
规则:开了必须关,否则报错

元素的嵌套,这是他最强大的特性:
```html
<订单>
      <客户>
          <姓名>张三</姓名>
          <电话>138-0000-0000</电话>
      </客户>
      <商品>
          <名称>笔记本电脑</名称>
          <价格>8999</价格>
          <数量>1</数量>
      </商品>
</订单>
```
并且还有一条规则:永远只能有一个根元素,那在上面代码中 <订单></订单>就是根元素,根元素并不固定是特定标签,那么下面的那些 <客户> 之类的,被称为 子元素
```html
<订单>
      <客户>
          <姓名>张三</姓名>
          <电话>138-0000-0000</电话>
      </客户>
      <商品>
          <名称>笔记本电脑</名称>
          <价格>8999</价格>
          <数量>1</数量>
      </商品>
</订单>
<商场>
...
</商场> //报错,并且商场不是根元素,而是根元素超过了一个
```

属性:就像便利贴一样
```xml
<学生 学号="2024001" 性别="男">
      <姓名>张三</姓名>
</学生>
```

那什么时候决定用 属性 还是 子元素?
- 当需要描述一个内容是干什么的时候,用 属性
- 当需要展示实际的内容的时候,用 子元素
